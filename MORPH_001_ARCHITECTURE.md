# MORPH-001 architecture and interface

Written after the repository/donor audits and before engine implementation.

1. moebius-morph: headless serde-versioned WormSpec (seed, length, radius/profile/aspect, curvature/resolution, mouth aperture/depth/width, flagellar surface coordinates/length/radius, optional ridge descriptors, appearance). Validation bounds finite values and topology budgets. Independent seeded generation; no Bevy, World, controller, Blender, LLM or service dependency.
2. CompiledWorm validates the definition and retains parametric topology/deformation controls. pose(Pose) emits indexed Surface meshes with normals, UVs and colours plus AttachmentFrames and explicit non-functional mechanical metadata. CPU deformation updates positions/normals while preserving indices. Ring sweep is selected because the first family has one axial trunk and two nonbranching tubes; it avoids a needless isosurface/remesh dependency. It is not a universal topology claim.
3. moebius-morph-lab: isolated Bevy0.20 consumer. Keyboard/Text editor, orbit camera, seed/length/thickness/mouth/flagella controls, body animation toggle and JSON save/reload. Changes validate/compile transactionally before replacing the preview. Pose animation is labelled authored preview, not neural control or emergent swimming. A deterministic capture harness exercises the same edit commands and save/reload path.

Body topology: capped tail, cross-sectional rings, annular lip, real recessed throat with a closed interior base. The closed-mouth limit retains a small positive seam to avoid collapsed triangles. Ridge modulation changes the generated body surface, not an unaccounted physical capability. Two configurable flagella are independent closed tubes; roots use barycentric coordinates on actual body triangles every pose. Overlap-mounted roots are deliberate, not a claimed welded manifold union. Export attachment frames and source triangle/barycentric bindings for future headless consumers.

G1/G5 compare serializable definitions and stable geometry digests at identical poses under the same environment. Cross-platform f32 transcendental bit identity is not promised. G2 checks finite data, legal indices, triangle areas, winding, unit normals, closed edge incidence and root attachment error. G3 runs at least100 seeds including distinct body/mouth proportions. G4 evaluates multiple explicit poses and live frames; self-intersection/visual clipping is reported separately from local manifold checks. G6 runs the existing workspace and verifies pre-slice source hashes for all simulation/Worm_A files.

Limits deliberately excluded: physical swimming, bite/contact laws, reproductive mutation, learning, arbitrary branching limbs, automatic retopology, general physics rigs, Zeitgeist integration and a complete drag-and-drop creator. Engine data and API are independently reusable; the laboratory is one consumer rather than the owner of anatomy generation.
